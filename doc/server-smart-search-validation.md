**服务端智能搜索实施与验收记录（2026-09-06）**

已实现 Rust 服务端本地混合搜索，并接入站点、签到任务、刷流任务和签到日志页面。三个子 agent 按用户指定的 GPT-6 medium 分工完成编码器/资产、搜索核心、数据库/API，主 agent 完成前端、集成与验收。计划见[实施计划](server-smart-search-plan.md)。代码、模型、公共目录与重生成向量均纳入本次交付。用户审阅结果后确认实际站点规模较小，并授权提交、推送当前实现及其他未提交改动。

功能与本地回归已通过；用户已授权按当前实际使用规模交付。**下列原始设计门槛没有全部通过，保留实测限制**。中文相关度仍低于参考混合检索；1,000 站点/10,000 任务的延迟与内存未达目标；其他平台的实际运行与安装包还未全部验证；正式 Linux musl 目标的压缩样包增加约 6.06 MiB、60.6%，需要按实际体积要求判断。这里保留这些限制，不把设计目标写成成绩。

**实现范围**

| 部分 | 实际行为 |
|---|---|
| 搜索位置 | Rust 进程内完成解析、匹配、向量推理、排序、计数和分页；浏览器只发请求并展示记录 |
| 本地身份 | 任务关联本地 `site_id`；自定义站名可修改、可重复，不靠名字识别公共站点 |
| 目录关联 | 已验证域名自动识别、手动指定、不关联；改地址重新识别自动关联，手动选择保留 |
| 文字检索 | 自定义名称、别名、域名、用户名/UID、原有 PTD 标识、任务名/标签/消息；全拼、分段完整拼音、首字母与受控错拼 |
| 条件与排序 | 真实状态、指定站点/ID/类型/集合为硬条件；精确名称优先；描述片段采用概念与向量，不能绕过硬条件 |
| 语义资产 | 308 个目录站点、300 对有出处的 PTD 映射、616 个 384 维向量；由最终 Rust 编码器生成 |
| 编码器 | 固定 mini 权重和 tokenizer，原生 CPU 推理；无运行时 Node、WASM 引擎或首次启动模型下载 |
| 记录搜索 | 搜索完整签到历史，256 行分批处理，SQLite 临时表全局排序；不先截取 100/500 条再搜索 |
| 界面 | 防抖、输入法保护、旧响应丢弃、清除识别条件、服务端页码修正、错误重试、目录选择、同名账号编号 |
| 状态刷新 | 手动执行和刷流启动后，可见页面短时轮询两分钟；串行请求且保留同查询数据，也提供手动刷新 |
| 发布维护 | 资产/模型校验、核心/API 检查加入发布流程；MIT 通知与来源信息随 CLI、Docker、桌面包提供 |

预生成目录向量只编码公开站点描述；查询向量在服务端内存中计算。用户配置、凭据、真实查询和任务数据不进入公共文件；新搜索字段不扫描完整配置或 RSS 查询参数。原有消息搜索仍保留。站点搜索复用现有安全响应结构，不返回认证配置。

数据库迁移取消 `sites.name` 的唯一约束，保留本地 ID、外键关系、自增序列及现有索引/触发器。站点保存与关联保存是两个请求：关联失败后保留已创建 ID，重试更新该记录，避免重复创建。用户已有站点页面、备份和 NexusPHP 改动已保留。

**服务端延迟与内存**

测量环境为 Linux x86_64 GNU、Intel N150，实际允许四个 CPU 核心，无 CPU/内存配额。使用优化后的完整发布二进制，通过 HTTP 测量；数据为 300 站点、150 签到任务、150 刷流任务，以及单独扩展到 100,000 条的签到历史。它与编码器报告中的双核独立推理基准不同。完整样本、二进制 SHA256、夹具和原始耗时见[最终 HTTP 数据](validation/server-smart-search/http-final.json)。

| 场景 | 实测 |
|---|---:|
| 首次混合搜索，含冷初始化 | 66.30 ms |
| 文字热查询 p95（20 次） | 7.34 ms |
| 混合热查询 p95（20 次） | 16.76 ms |
| 四路混合查询，12 次请求 | 全部 200、使用语义且计数/当页 ID 一致；最慢 53.81 ms |
| 10 万条历史，空查询深页 | 50.22 ms；总数 100,000 |
| 10 万条历史，稀有文字 | 8.34 秒；精确返回 1 条 |
| 10 万条历史，状态文字查询 | 7.85 秒；精确总数 33,333 |
| 同时发起 8 个历史扫描 | 1 个约 9.66 秒完成，7 个在 1.78–3.54 ms 内返回 503 |
| 历史扫描期间另外 3 个普通搜索 | 全部 200，16.72–17.56 ms |
| 搜索前整进程 RSS | 21.32 MiB |
| 最终压力场景整进程峰值 RSS | 83.96 MiB |
| 相对搜索前额外峰值 RSS | 62.64 MiB |

首次压力测试发现，四个并行历史扫描的额外 RSS 达到 89.23 MiB，并在 15 秒超时。随后增加独立的单个历史扫描配额，同时保留全局四个搜索配额；空查询分页走 SQLite 批量路径。最终压力场景满足该夹具下额外 64 MiB 的初步目标，普通查询仍可处理。原始失败结果保留在[限流前数据](validation/server-smart-search/http-before-history-limit.json)。

历史扫描设有 15 秒期限，SQLite 进度检查和逐批检查共同中断超时操作。工作线程退出前不释放配额，客户端放弃请求也不能造成无限后台工作。繁忙时返回可重试的 503，超时返回 504；没有无上限等待队列。

10 万条历史的描述/内容搜索需要扫描数据，**不满足普通列表 200 ms 的延迟目标**。当前提供精确计数和有界资源处理，任务/站点筛选可缩小范围；该限制不能由“模型推理约十毫秒”掩盖。这些数字是单台设备的实际观测，不代表任意数据规模或硬件的性能保证。

| 文字 / 混合热查询 p95 | 8.92 / 19.05 ms |

**语义相关度与能力边界**

编码器使用固定 BERT uncased tokenizer，中文依赖共享中英文概念映射；不能把它当作通用中文语义模型。未识别的中文描述保守走文字检索，防止大量未知中文 token 导致虚高余弦相似度。已有功能支持纯英文描述与领域中文描述，固定词表之外的同义表达仍可能遗漏。

初始验收发现描述词被错误要求逐字出现、句尾标点和代词与短站点别名冲突等解析问题，现已按通用语法规则修复。之后分别保留旧失败样例、独立新样例和最终代码回归；未根据第三组结果反复调整阈值。共保存三组 30 条公开合成查询，相关度使用公开元数据与人工列出的专门站点进行分级，属于小型领域代理标注。

| 第三组：20 条描述、10 条无关查询 | NDCG@10 | Precision@5 | 无关查询返回结果 |
|---|---:|---:|---:|
| pt-sites 文字/概念 | 0.59539 | 0.93 | 3 / 10 |
| pt-sites 既有混合检索 | 0.86649 | 0.98 | 10 / 10 |
| 当前原生混合检索 | 0.82243 | 0.92 | 0 / 10 |

中文十条样例的 NDCG@10 为当前 **0.80043**、既有混合 **0.86463**；因此“中文不劣于既有混合检索”门槛尚未通过。相对文字/概念有明确的分级相关度增益，但不能宣称所有指标全面领先。既有目录检索默认给全部站点排序，不进行本项目的无结果门槛过滤，故 10/10 不能解读为它的模型本身完全无法识别无关内容。

查询与目录使用同一份概念规则，原生 tokenizer/浮点结果的参考一致性已经验证；新旧描述模板和排序规则仍有差异，不能由编码器一致推导最终排序一致。原有 pt-sites 的圈别、语言、站点形式等信息没有全部进入本次资源/特色模板；注册信息也不作为实时筛选依据。本次不把缺失信息推断为站点事实。

最后的共享多词概念、分段拼音与两次缓存同步修复又在原第三组上做了回归，30 条查询的完整结果顺序和语义状态均不变；这些复测明确作为回归，没有重新声称它们是未知样例。完整出处、困难查询前五条、历史结果及代码哈希见[编码器与相关度报告](search-encoder-validation.md)和[最终回归数据](../assets/search/evaluation-final-regression-results.json)。

**平台和发布状态**

**复现入口**

常规代码与资产检查不依赖相邻 pt-sites；模型和索引由仓库文件提供，首次获取普通 Cargo/npm 依赖仍需要通常的依赖缓存或网络。
