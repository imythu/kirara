**服务端智能搜索实施计划**

依据：[设计方案](server-smart-search-design.md)。用户已授权实施，并指定子 agent 使用 GPT-6 medium；当前工具对应模型为 `gpt-6-astra`，`reasoning_effort=medium`。

- [x] P0：保存当前工作区基线，验证原生查询编码器、权重来源、中文样例和打包成本。
- [x] P1：实现公共资产生成及校验，将元数据、模型和 Rust 生成的向量文件加入工作区。
- [x] P2：实现站点身份关联、拼音、查询解析、匹配、排序、语义检索和单元验证。
- [x] P3：实现数据库关联迁移、四类业务搜索与公共目录选择接口、服务端计数与分页。
- [x] P4：接入站点、签到、刷流与签到日志页面，处理输入法、防抖、响应竞态及错误状态。
- [x] P5：完成当前使用规模的交付检查并按用户指示提交、推送。用户确认不会达到 1,000 站点/10,000 任务规模，该压力场景保留为参考；中文相关度差距和非 Linux 平台验证继续作为已知限制，不记为测试通过。

分工与文件所有权：编码器 agent 负责 `crates/search-encoder/`、`assets/search/`、生成工具；搜索核心 agent 负责 `src/search/` 与搜索核心样例；接口 agent 负责数据库、服务端接口及 OpenAPI；主 agent 负责根 Cargo 配置、前端、计划与验收报告。共享契约通过消息明确，避免同时修改同一文件。

本轮在确认原生编码器可离线运行、参考输出一致以及初步体积后进行了接口和页面集成。中文相关度与全部目标平台的验收仍未通过，因此技术上可运行不等于模型选型已经完整验收。质量、性能和预算的不足以实测证据记录，没有静默取消向量功能。

实施期间保留用户已有改动，未操作真实用户数据库或启动真实站点任务。用户在审阅实测结果后要求提交、推送本次实现及其他未提交改动；发布与推送按这一授权执行。包含账号凭据的备份单独处理。

实际实现使用 308 个公共站点、300 对有出处的 PTD 映射、616 个原生生成向量。固定模型与 tokenizer 随代码提供；浏览器不加载搜索模型。自定义站点名、同名账号、改名、手动/自动/不关联三种方式均保留本地 ID 关系。

共 543 项 Rust 库测试通过，另有前端浏览器交互、临时数据库 HTTP、编码器一致性与资产验证。最终体积、压力测试、语义相关度、平台执行范围及设计取舍集中记录在[验收报告](server-smart-search-validation.md)。未将有限样例或跨平台类型检查当作完整发布认证。

Linux x86_64 GNU 与实际发行所用 musl 目标的完整程序都已构建，最终版本均通过 32 项临时数据库 HTTP 检查；musl 的两个 CPU 核心测量中，混合热查询 p95 为 19.05 ms，额外峰值 RSS 为 28.94 MiB。

1,000 站点、10,000 任务的双核压力测试已完成，34/34 项正确性检查通过；四路任务混合查询 p95 约 2.76–2.96 秒，额外峰值 RSS 160 MiB，延迟与内存均未达设计目标。详见报告，未将较小夹具的成绩替代该规模验收。

后续改进记录：中文相关度进一步验证与改进；Windows x64、macOS ARM64、Linux ARM64 实际运行与安装包测量；更大任务规模的候选处理和内存优化。用户已了解 musl 压缩包增加 6.064 MiB、约增加 60.6%，并授权提交当前版本。原生编码器、资产和桌面测试已接入发布流程，远程 CI 状态以实际运行结果为准。
