# RSS 下载使用说明

在「资源与订阅 → RSS 下载」（`#/rss`）中，先添加订阅源，再创建下载规则。模块按标题与种子属性收取新资源，复用现有站点配置和 qBittorrent 下载器，不依赖 TMDB。

## 第一次使用

1. 在「下载器」中配置 qBittorrent。也可以先添加 RSS 源、浏览条目，稍后再配置下载器。
2. 打开「RSS 下载 → 订阅源 → 添加订阅源」，填写名称和 RSS 地址。地址保存后不可修改，请先测试；要使用其他地址，请添加新的订阅源。含独立 Passkey 的地址可以不关联站点。RSS 与关联站点的 API 地址可以使用不同域名；RSS 按订阅链接读取，站点接口用于查询属性和获取种子。
3. 点击「测试并预览」，查看解析数量和最多 20 条样例。此操作不保存历史，也不会下载。
4. 保存订阅源。第一次成功检查只建立历史基线，即使源中已有很多资源，也不会自动补下。
5. 为此源创建规则：选择来源、包含词与排除词、目标下载器，可以设置目录、分类、标签和暂停添加。
6. 点击「查看匹配结果」。后端给出符合、被排除、信息不足及逐项原因；「读取最新资源」可读取远端的新样例，同样不会创建下载任务。
7. 点击「保存并启用」。只有规则生效后新发现的条目才自动匹配；想下载已有条目，应在源的条目列表中勾选资源，再点击「补下已有条目」。

「立即检查」会运行真实抓取和匹配，可能创建下载任务；它与只读测试、规则预览不同。检查请求返回后，可以查看处理记录中的匹配、待处理和入队数量。

## 配置规则

表单按「从哪里找资源」「下载哪些资源」「下载到哪里」组织。每项设置旁说明用途；关键词、H&R、保存目录和空间计算的详细解释可点击展开。文件大小、做种人数、正则、分类标签和执行设置默认收起，编辑时已配置的选项会展开显示。

一条规则可以选择多个 RSS 源，指定一个下载器。同一资源在同一个下载器上按优先级数值从小到大选择规则，同优先级按规则 ID 排序；不同下载器可分别投递。

| 条件 | 含义 |
|---|---|
| 包含词 | 默认全部满足，可切换任意满足；按标题子串匹配 |
| 排除词 | 任意命中就拒绝 |
| 正则 | Rust regex 语法，不支持环视和反向引用；单项最多 512 字符 |
| 接收所有标题 | 不要求标题包含关键词或匹配包含正则，仍遵守排除词、排除正则和其他条件；切换回标题筛选可继续编辑原来的输入 |
| 大小、做种数 | 大小区间包含边界；缺失值保持未知 |
| 仅免费 | 需要可靠的免费属性，标题中的 `[FREE]` 不作为充分证据 |
| H&R | 默认仅接受确认无 H&R 的资源；也可明确选择不限制 |
| 容量保护 | 扣除未完成下载量和 RSS 尚未体现在采集结果中的预占，再保留指定剩余空间 |

标题统一 Unicode NFKC、大小写和空白后匹配，原始标题仍用于显示。关键词每组最多 50 项，每项最多 100 字符。不同类型条件之间为 AND。

未知不等于 0、免费或无 H&R。若源缺少规则需要的属性，后台只对候选资源尝试关联站点查询；站点不支持可靠属性时，条目保持信息不足。预览只使用样例已有属性，不执行站点详情补充，因此自动处理取得新证据后的结果可能与预览不同。

提交前会校验种子、使用实际文件大小再次匹配，并复核免费和 H&R 证据的时效。免费资格已经失效或无法取得新证据时，任务等待确认，不会按旧的免费标记提交。

## 暂停、编辑与历史补下

| 操作 | 结果 |
|---|---|
| 暂停源 | 停止抓取，挂起该来源尚未提交的任务 |
| 暂停规则 | 停止新匹配，挂起该规则尚未提交的任务 |
| 恢复 | 继续已入队任务；默认不补下暂停期间出现的资源 |
| 恢复此前未抓取的源 | 下一次成功响应先建立恢复基线，再收取之后新增的条目 |
| 修改规则筛选、来源或目标 | 新版本用于后续条目；原队列保留入队时的规则和选项 |
| 使用其他 RSS 地址 | 添加新的订阅源；已保存的地址不可修改，原来源的历史和任务保持独立 |
| 更新站点 Cookie / API Key | 后续请求使用新凭据，不重建 RSS 历史基线 |
| 归档源或规则 | 停止新工作并取消确认未提交的任务，保留已经发出请求的对账及成功历史 |

已经发出的提交即使遇到暂停或归档，也必须确认远端结果，不能直接宣称取消成功。RSS 归档和取消不会删除 qBittorrent 种子或文件。

补下每次最多选择 200 条已保存资源，需要一个覆盖这些来源的启用规则。它只放宽历史生效边界，仍执行规则、去重、周期配额、种子校验及空间检查。已成功提交的资源不会通过普通重试或补下重复添加。

## 看懂下载记录

| 投递状态 | 意义与处理 |
|---|---|
| 已入队 / 正在取种 | 持久化请求已保存，后台准备种子和目标 |
| 已挂起 | 源或规则暂停；恢复后继续。来源已更换的旧任务只能取消 |
| 等待条件 | 空间不足、属性待确认或相同种子正在转移；条件满足后重试 |
| 正在提交 | 已保存哈希及提交意图，正在联系下载器 |
| 正在对账 | 尚未确定远端是否接收；使用实时查询确认，下载器离线不等于不存在 |
| 已提交 / 已存在 | 下载器已确认接收或去重命中；这不表示文件下载完成 |
| 等待重试 / 失败 | 普通失败最多尝试 5 次，间隔约 1、5、15、60 分钟；修复后可手动重试 |
| 已取消 | 确认尚未提交的任务停止执行 |

下载中、暂停、做种、完成及进度来自下载器采集，与投递状态分别显示，并附采集时间。已经提交的种子后来被手动删除，会显示下载器中未找到，系统不会自动重新下载。

认证失效时前往站点配置修复；下载器不可达时检查下载器配置；提交结果不明时使用「确认添加结果」。发生版本冲突时，保留草稿，刷新对象状态后再操作。

## 首版支持与限制

- 支持 RSS 2.0、常见 Torznab 属性、UTF-8 / UTF-8 BOM 和 `.torrent`。Atom、RSS 1.0、其他编码、磁力链接直投和普通附件暂不支持。
- 优先使用 RSS 中的种子链接；链接失效或未提供链接时，根据稳定种子 ID 使用关联站点的认证信息，通过 NexusPHP / M-Team 适配器重新获取同一个种子。属性补充依赖站点和认证类型，不承诺所有站点都能判断 H&R。
- 默认每 15 分钟检查，可设置 5–1440 分钟。每源每个成功检查周期最多创建 20 个下载任务，超额项持久化等待后续周期。手动检查也遵守站点冷却。
- 源响应上限 8 MiB、每次最多 1000 条；种子上限 64 MiB。超限或损坏响应不会推进历史基线。
- 剩余空间是 qBittorrent 报告的磁盘空间，不能据此确认自定义保存目录所在的另一块磁盘。未提供有效空间数据时不会按已确认的 0 字节处理，也不会跳过检查继续提交。
- RSS 内部按来源身份、站点种子身份和下载器内 infohash 去重；与媒体/刷流同时首次添加仍可能竞争分类、目录等选项。首版未提供跨模块统一投递仲裁；与种子转移已有双向事务互斥。
- RSS 只提供远端当前保留的条目。服务离线期间已从远端消失、且本地从未见过的内容无法自动补回。
- 详细历史保留约 30 天，活动任务不清理；精简已见身份和成功投递墓碑继续保留，防止清理后重下。数据库沿用现有本地凭据保存模型，不新增加密承诺。

RSS 地址仅在新增时填写，编辑时只展示隐藏了私密信息的地址。名称、关联站点、检查间隔和代理设置仍可修改。代理默认继承关联站点；未关联且没有显式选择代理时直接连接。

## API 与开发验证

完整路由在 [OpenAPI 主文档](openapi.yaml)，RSS 定义通过外部引用组织在 [rss-openapi.yaml](rss-openapi.yaml)。所有请求使用同一 Web / 桌面 JSON API。更新与状态操作携带 `expected_version`；创建和操作可使用 `request_id` 防重复，历史补下必须提供。检查与补下返回 `202` 和 `RunRecord`，使用响应的 `id` 查询 `/api/rss/runs/{id}`。

实现说明与验收项目见 [完整设计](rss-downloader-design.md)。可复现的检查命令：

```bash
cargo test -p kirara --lib
cargo test -p kirara --test rss_downloader --test server_lifecycle
npm --prefix frontend run check:rss
npm --prefix frontend run build
npx --yes @apidevtools/swagger-cli validate doc/openapi.yaml
```

浏览器用例为 `frontend/tests/rss.browser.cjs`，需要已安装 Playwright 和 Chromium。构建完成后，在一个终端启动预览，在另一个终端运行用例：

```bash
npm --prefix frontend run preview -- --host 127.0.0.1 --port 4189
```

```bash
RSS_TEST_URL=http://127.0.0.1:4189 node frontend/tests/rss.browser.cjs
```

Playwright 不在默认依赖目录时使用 `PLAYWRIGHT_MODULE` 指定已安装的位置。用例使用明确标记的合成数据检查 1440px / 390px、Web 与桌面 IPC 协议、字段错误、草稿保留、失败重试和轮询；Rust 集成测试通过本地 RSS / qBittorrent 模拟服务验证真实 HTTP 客户端、数据库和后台调度。未使用真实 PT 账户，也未验证 Windows/macOS 打包后的原生窗口。
