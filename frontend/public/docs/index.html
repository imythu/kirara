云母使用手册

从连接第一个站点，到让订阅和定时任务持续运行。按下面的顺序完成首次配置，之后可通过目录直接查找功能。

本文随应用内置，无需联网加载文档。使用浏览器的 Ctrl / ⌘ + F 查找关键词；目录链接可收藏并直接打开对应章节。

开始使用

云母集中管理 PT 站点、qBittorrent 下载器、影视订阅和自动任务。Web 版通过浏览器连接运行中的服务；桌面版打开应用即可使用。

第一次配置，按这个顺序

  1. 连接站点：在「站点管理」添加 PT 站点，填写对应的 Cookie 或 API 凭据，并测试连接。已有 PTD 配置可先导入站点 Cookie。
  2. 连接下载器：在「下载器」添加 qBittorrent，测试连接，确认能读取磁盘和种子信息。
  3. 准备影视订阅：进入「自动追剧 → 质量与设置」，填写 TMDB API Key 或 Read Access Token，检查扫描设置及质量方案。
  4. 完成一次手动操作：从「TMDB 添加」创建订阅并立即扫描，或在「资源搜索」查找资源、选择下载器提交。
  5. 确认结果：查看下载队列，再到 qBittorrent 检查实际进度。确认配置正确后，再开启 RSS、刷流或签到等定时任务。
选对功能：按影视季集持续追更用「自动追剧」；按 RSS 标题和属性收取新种用「RSS 下载」；需要按选种、删种规则运行的 PT 任务用「刷流任务」。RSS 下载不依赖 TMDB。

桌面宽屏使用左侧菜单，手机通过菜单按钮切换功能；菜单支持按名称查找。GitHub 图标旁的书本图标在新标签页打开本手册。

站点管理

添加与验证站点

  1. 打开「站点管理」，添加站点并选择适配的站点类型或预设，填写名称和站点地址。
  2. 按所选认证方式填写 Cookie、API Key 等凭据。NexusPHP Cookie 页面抓取、NexusPHP API 和 M-Team 的认证要求不同，应以当前表单为准。
  3. 如需代理、自定义请求头、Passkey 或搜索绑定，在对应配置中填写。站点账号抓取成功后，也应通过一次资源搜索确认搜索适配可用。
  4. 保存后测试连接并刷新账号数据，检查用户名、上传量、下载量、分享率等是否符合预期。

Cookie 应来自已登录该站点的浏览器，不要填写另一域名的 Cookie。过期后重新登录站点获取，或使用 PTD 同步更新。已保存的秘密字段不会明文回填；编辑时留空保留原值，只有明确清除才删除。

查看账号数据

站点列表展示最近采集的账号数据，可刷新并查看同步时间。导出账号总览图片适合保存或分享统计结果；图片不是可恢复的数据库备份。刷新失败时先检查登录状态、网络和代理，再查看错误说明。

PTD 导入与备份

在「站点管理」的添加操作菜单选择「导入 PTD 数据」，进入「从备份导入」。Web 版和桌面版均可使用，无需开启 WebDAV。

  1. 在安装 PTD 的浏览器中登录要导入的站点。进入 PTD「常规设置 → 备份恢复」，暂时将「备份文件加密、解密密钥」留空；保留原密钥，导出后可恢复原设置。
  2. 在「参数备份与恢复 → 本地导出」勾选「站点 Cookies（cookies）」并导出。不同 PTD 版本的入口名称可能略有差异。
  3. 回到云母选择未加密的 PTD_backup_*.zip，或解压出的 cookies.json，文件不超过 8 MiB。
  4. 选择已有站点「更新 Cookie」或「跳过」，并决定是否自动添加可识别的新站点，然后点击「开始导入」。
  5. 核对新增、更新、未变化、跳过及具体原因。导入后站点列表会刷新，可再测试连接。

仅导入站点与 Cookie，不恢复下载器、任务或 PTD 插件偏好；更新已有站点时保留其他配置。存在多个匹配账户、不支持的站点或不适用的认证方式时会跳过，请按结果逐项处理。本次导入选项不修改自动同步设置。

同步到蜂巢

在「站点管理」打开「同步到蜂巢」，填写接收方提供的 WebDAV 地址、用户名和密码，先测试连接，再点击「保存并备份」。此功能向外发送站点账户数据与历史统计，用于蜂巢「PT 人生」展示，与接收 PTD Cookie 的方向不同。

需要定时发送时启用「自动备份」，设置周期（1–720 小时）并保存；系统在站点统计刷新完成后检查周期。展开备份范围核对可识别站点，未识别项不会备份；保存后查看上次备份时间、文件名和失败原因。

要完整恢复云母的订阅、任务和运行记录，请备份整个数据目录。

Cookie 自动同步

此功能接收 PTD 定时推送的未加密备份，自动更新站点 Cookie。接收服务与 Web 服务共用端口；桌面版没有对外 Web 端口，需使用 Linux / Docker Web 服务来接收。

  1. 进入「站点管理 → 导入 PTD 数据 → 通过 WebDAV 同步」，启用接收服务，设置已有站点处理策略及是否自动添加新站点。
  2. 保存配置，复制页面显示的接收地址、用户名和本次生成的密码。地址路径为 /dav/ptd/，无需另开端口。
  3. 将三项填入 PTD 的 WebDAV 备份设置，关闭 Digest，选择包含 Cookie 的未加密备份，并设置自动备份周期。
  4. 先手动推送一次，再回云母查看同步记录，核对每个站点的处理结果。
上传成功 ≠ 站点全部更新成功。PTD 上传成功表示备份已接收，新增、更新、跳过和失败原因应在云母同步记录中查看。可重试的失败记录支持「重新同步」；数据已清理时需重新推送。

接收密码只在生成时显示；重新生成会立即替换旧密码，同时保存当前表单，必须同步更新 PTD 的连接配置。该密码仅用于 WebDAV 接收，不是云母管理界面的登录密码。

从另一设备推送时，接收地址应使用对方可访问的运行机器地址；对方的 localhost 指向对方自身。反向代理需完整转发 /dav/ptd/ 路径及 WebDAV 方法、认证请求头。较旧来源时间的备份不会覆盖已经应用的新数据；发送设备时间异常时先校正时钟。

下载器与空间分析

  1. 在 qBittorrent 中启用 Web UI，确认云母所在机器能访问其地址和端口。
  2. 打开「下载器 → 添加下载器」，填写名称、URL、用户名和密码。URL 是 qBittorrent Web UI 地址，例如 http://192.168.1.10:8080（示例，请替换）。
  3. 保存并测试连接；进入详情核对连接信息、种子和空间数据。
  4. 在订阅、RSS 规则或刷流任务中选用该下载器，并填写它实际可访问的保存目录。

云母运行在 Docker 中时，127.0.0.1 指向云母容器本身。qBittorrent 位于另一个容器或宿主机时，应填写容器网络名称或实际可达地址。保存路径按 qBittorrent 所在环境填写，例如其容器内的挂载路径。

查看保存路径占用

进入下载器详情的「保存路径占用分析」，可按分类、标签多选筛选，再搜索路径、种子名、标签或分类。查看各目录的种子数、数据量和待下载量，展开目录定位具体种子；刷新后留意采集时间。

数据总量和待下载量来自种子统计，不能直接当作操作系统实际占用。剩余磁盘空间由 qBittorrent 报告，也不代表每个自定义目录所在磁盘的空间。

自动追剧与电影订阅

从 TMDB 创建订阅

  1. 在「质量与设置」保存 TMDB 凭据，确认已有可用站点和下载器。
  2. 进入「TMDB 添加」，搜索影视名称并选择正确的电影、电视剧或动漫；核对年份及作品身份，避免同名作品。
  3. 电视剧选择季和起始集。动漫可按季集或绝对集编号设置，编号应与目标发布资源一致。
  4. 选择质量配置、搜索站点、下载器和保存路径，然后创建订阅。
  5. 回到订阅列表立即扫描，查看最近扫描结果和关联下载任务，确认首个目标匹配正确。

系统根据 TMDB 元数据确定当前应搜索目标，尚未播出的剧集不会提前下载。成功提交当前集后会推进目标；提交不等于文件已完成下载，实际进度以下载器为准。

日常管理与排查

订阅支持暂停、恢复、立即扫描和编辑。需要从中间开始追剧时，修改季、起始集或绝对集；想换下载位置或清晰度时，修改该订阅的下载器、路径或质量配置。

扫描详情会显示搜索词、候选、站点错误和拒绝原因。错剧、错季、错集、禁止的质量及做种数不足会明确拒绝，不会因其他项分数高而自动放行。没有合适结果时先核对目标和规则，再决定是否手动选种。

当前不支持 scene/XEM 编号映射、每日剧日期编号和整季自动升级。动画编号不一致时应人工核对，不能假定绝对集会自动映射成任何站点的季集编号。

质量配置

进入「自动追剧 → 质量与设置」创建或编辑质量配置，再在订阅或资源搜索时选用。首次使用可直接从内置方案开始。

方案主要偏好
电视剧 · 日常1080p WEB-DL，兼顾更新速度与体积。
电视剧 · 4K优先 2160p WEB-DL，1080p 作为备选。
电影 · 收藏优先 2160p、REMUX、BluRay。
电影 · 均衡偏好 1080p BluRay、WEB-DL。
动漫 · 日常优先 2160p，兼容常见字幕组命名。
动漫 · 省空间偏好 1080p H.265、AV1，拒绝 4K。

高级规则可调整分辨率、片源和编码的允许值、拒绝值及优先级，以及最低匹配分、最低做种数和是否接受未知质量。优先级用于排序，拒绝条件决定能否放行。例如希望 1080p 为主但接受 4K，就应允许两者并调整排序；完全不想要 4K，则应明确拒绝。

HDR、Dolby Vision、Dolby Atmos、DIY、10bit 等标题信息供人工参考，当前自动质量筛选主要依据分辨率、片源和视频编码。

「恢复默认」会重置已有配置。它会删除现有质量配置，重建六套内置方案，并将全部订阅切换到「电视剧 · 日常」。操作不可撤销，确认前先记录需要保留的自定义规则。

资源搜索与下载队列

手动搜索与选种

  1. 在「自动追剧 → 资源搜索」输入关键词，选择一个或多个站点，可选质量配置后搜索。
  2. 若是为已有订阅选种，选择该订阅带入当前电影、季集或绝对集目标；这种模式会进行更严格的影视身份校验。
  3. 比较标题、站点、大小、做种数、发布时间、解析质量和拒绝原因。某一站点失败不会影响其他站点结果返回。
  4. 确认候选后选择下载器和保存位置，加入下载队列。被规则拒绝的资源若要手动覆盖，必须填写原因。

覆盖只影响本次下载，不会修改质量方案。先核对是否选错作品或集数，再使用覆盖。纯关键词搜索适合临时查找，不能替代订阅目标的身份检查。

队列状态怎么看

自动扫描和手动搜索共用持久化队列，依次完成取种、校验、提交和对账。系统按下载器与真实 infohash 去重，临时失败会重试；提交结果不明确时先查询 qBittorrent，避免重复发送。

遇到等待重试或失败，查看任务错误，修复站点凭据、下载器连接或目录后再操作。最终失败时关联剧集会恢复为待搜索。队列完成表示投递流程完成，文件下载进度仍需查看 qBittorrent。

RSS 下载

RSS 按标题和种子属性匹配新条目，不依赖 TMDB。配置分为订阅源、规则和下载记录，复用站点及 qBittorrent 配置。

添加源并启用规则

  1. 进入「RSS 下载 → 订阅源 → 添加订阅源」，填写名称和 RSS 地址，可关联站点以补充属性或获取种子。带独立 Passkey 的链接可不关联站点。
  2. 点击「测试并预览」确认能解析资源。此操作只读，不保存历史也不下载。确认地址后保存；保存后的 RSS 地址不可修改，更换地址请新增订阅源。
  3. 第一次成功检查只建立历史基线，不会把源里已有的全部资源下载下来。
  4. 创建规则，选择来源，填写标题包含词和排除词，选择下载器；需要时展开大小、做种数、分类、标签、目录和执行设置。
  5. 点击「查看匹配结果」，检查符合、被排除和信息不足的原因。「读取最新资源」仍然只读。
  6. 点击「保存并启用」，后续新发现的资源才进入自动匹配。要下载历史资源，在源条目列表勾选后使用「补下已有条目」。
「立即检查」会真实运行。它会抓取、匹配并可能创建下载任务，与只读测试和规则预览不同。操作后查看处理记录和下载记录。

筛选条件怎么填

  • 包含词：每行一个或用逗号分隔；「全部满足」要求每个词都出现，「任意满足」只需一个。例：两行填写「纪录片」与「1080p」，选择全部满足。
  • 排除词：任意一个命中就跳过，例如「预告片」「花絮」。匹配不区分大小写，并统一常见空白和字符形式。
  • 接收所有标题：取消标题包含条件，仍执行排除词和其他属性规则。
  • 正则：使用 Rust regex 语法，不支持环视和反向引用；普通需求优先使用关键词。
  • 大小与做种数：填写范围或阈值；未知属性不当作 0。不同类型的条件需要同时满足。
  • 仅免费 / H&R：需要可靠属性，标题中的 FREE 不足以证明免费。默认仅接受确认无 H&R 的资源；明确选择不限制才放宽这一条件。
  • 容量保护：从可用空间中扣除未完成下载量及预占，再保留指定剩余空间。实际提交前仍会再次检查。

同一资源在同一下载器上按规则优先级数值从小到大选择，同优先级按规则 ID 排序。预览不补查站点详情，真实处理可能取得更多属性；信息不足时先检查关联站点和凭据，勿把未知当作免费或无 H&R。

暂停、补下与下载记录

暂停源会停止抓取并挂起其尚未提交任务；暂停规则会停止新匹配并挂起该规则的待提交任务。恢复后继续已入队任务，默认不补下暂停期间的历史内容。修改规则后，原队列保留入队时的配置。

「补下已有条目」每次最多选 200 条，需要覆盖来源的启用规则，仍遵守筛选、去重、配额和空间限制。默认每源每次成功检查最多创建 20 个任务，超额等待后续周期；默认检查间隔 15 分钟，可设为 5–1440 分钟。

状态如何处理
已入队 / 正在取种后台正在准备种子与下载目标，等待处理。
已挂起检查源或规则是否暂停，恢复后继续。
等待条件查看空间或属性待确认原因，条件满足后重试。
正在提交 / 正在对账远端结果可能尚未确认。恢复下载器连接，必要时使用「确认添加结果」。
已提交 / 已存在下载器已确认接收或已存在，不代表文件下载完成。
等待重试 / 失败普通失败最多尝试 5 次；修复具体原因后可手动重试。
已取消确认未提交的任务已停止，不会因此删除 qBittorrent 文件。

归档源或规则会停止新工作，已发出的请求仍需完成对账。RSS 不自动删种；已经提交的种子被手动删除后，也不会自动重新下载。支持 RSS 2.0、常见 Torznab 属性和 .torrent，暂不支持 Atom、RSS 1.0、磁力链接直投。RSS、媒体和刷流之间没有统一投递仲裁，应避免用多个模块同时首次提交相同资源。

刷流任务

  1. 打开「刷流任务」创建任务，填写名称、站点、RSS 地址和标签。
  2. 选择一个或多个下载器；多选时按权重随机分配，数值越大越容易被选中。
  3. 设置 Cron 表达式，例如 0 */5 * * * * 表示每 5 分钟执行。此示例包含秒字段，不要直接套用五段格式。
  4. 设置做种体积上限、最低剩余磁盘空间和保存子路径；留空子路径时使用各下载器默认目录，检查表单显示的最终路径。
  5. 配置选种条件及删种规则，保存后手动执行一次，检查任务统计、种子状态和日志，再交给定时执行。

选种与删种

选种可限制促销类型、大小、做种/下载人数、最少免费时长、H&R、并发数和上下行限速；活动时间窗口进一步限制工作时段。免费及 H&R 信息来自 RSS 扩展属性，必要时由支持的站点补充。

删种配置包括最小做种时间、HR 最小做种时间、目标分享率、最大上传量、下载超时、最低平均上传速度和最大不活跃时间。「或」表示任一删除条件满足即可触发，「与」表示要求全部条件满足。结合站点要求设置做种保护，并在启用前逐项核对。

刷流包含实际下载和删种操作。先用小范围条件和有限容量观察一轮，不要将「RSS 下载不自动删种」的行为套用到刷流任务。

自动签到

  1. 先确保 NexusPHP 站点已添加，Cookie 有效。打开「自动签到」配置公共 Lightpanda 或 Browserless 连接，填写所需 Endpoint / 地址及 Token 并保存。
  2. 选择单个新增，填写名称、站点及执行间隔，按站点选择合适的签到方式；通常先使用对应站点预设。
  3. 需要一次添加多个站点时使用批量创建，选择尚无任务的站点并提交。检查每一项结果，失败项可保留重试。
  4. 手动执行一次，查看签到结果和执行记录。确认成功后保留定时执行；不再需要时暂停或删除任务。

每个站点最多一个签到任务，已暂停的任务也占用站点。如果创建列表中找不到站点，先检查它是否已有任务、是否为支持的类型。

高级方式包括页面签到、CF 页面挑战、CF Turnstile 和通用图片验证码。需要图片验证码识别时在「系统设置」配置 OCR API key；自定义元素和已签到提示文字应按站点实际页面填写。不要在普通站点上随意切换复杂方式。

失败时区分站点 Cookie 失效、浏览器服务连接失败、挑战未完成和页面元素变化。先修复对应配置，再手动执行并查看记录；批量创建成功不代表首次签到已经成功。

标签规则

按种子的 Tracker URL 给 qBittorrent 种子匹配标签，便于按站点整理与筛选。

  1. 打开「标签规则」新建规则，填写标签名并启用。
  2. 从已有 Tracker 中选择，或手动添加匹配条件；可用前缀、后缀、包含、完全匹配和正则。
  3. 核对候选匹配。例：按站点域名整理时，可使用包含条件 tracker.example.org（示例），避免仅填过于宽泛的 tracker。
  4. 选择生效下载器实例并保存，再查看对应种子的标签结果。

同一规则有多个条件时任一匹配即可生效。匹配对象是 Tracker URL，不是种子标题；站点更换 Tracker 域名后需更新规则。分享配置时不要泄露 URL 中可能包含的 Passkey。

总览、统计与日志

  • 系统总览：查看运行机器的 CPU、内存使用率和历史趋势；这不是当前浏览器设备的资源占用。
  • 数据统计：查看上传下载量、种子数及下载器趋势，结合筛选范围和采集时间判断。无历史采样时需要等待积累数据。
  • 实时日志：从工作台日志入口打开，可按等级和关键词筛选，检查连接状态；当前面板保留最近 500 行，适合查看正在发生的事件。

排查任务时先看对应订阅、RSS 或签到执行记录，再结合实时日志。日志等级从细到粗为 trace、debug、info、warn、error；前端筛选无法补回后端没有输出的低等级日志。需要细节时在系统设置保存更细等级，再复现问题。

系统设置

这里管理全局日志级别、代理与 OCR API key。影视扫描和质量选项在「自动追剧 → 质量与设置」，签到浏览器配置在「自动签到」。

  1. 根据排查需要选择全局日志级别；保存后立即作用于整个后端进程。
  2. 需要代理时选择 HTTP、HTTPS、SOCKS5 或 SOCKS5H，填写地址和端口。SOCKS5H 使用远程 DNS；无需代理则选择「不使用代理」。
  3. 在测试 URL 中填写希望验证的地址，点击「测试连接」，查看状态和耗时。测试完成后仍需点击「保存系统设置」持久保存配置。
  4. 需要图片验证码签到时填入 OCR API key 并保存。

代理地址必须从云母后端运行环境可达；容器中的本机地址不是宿主机地址。站点或 RSS 的代理选项应同时检查，避免全局测试通过但具体来源使用了不同配置。

数据备份与迁移

配置、凭据、订阅、任务和队列状态保存在本地 SQLite 中。升级或迁移前停止应用，备份整个数据目录，包含数据库及可能存在的 -wal、-shm 文件。

运行方式默认位置
Linux 服务./data/kirara.db；指定 --data-dir 时以指定目录为准。
Docker容器内 /data，备份其对应的宿主机挂载目录。
Windows 桌面%APPDATA%\io.github.imythu.kirara\kirara.db
macOS 桌面~/Library/Application Support/io.github.imythu.kirara/kirara.db

恢复时先停止目标程序，再复制完整数据目录并重新启动，核对站点、下载器、订阅和任务。旧数据库 rflush.db 无需重命名；同时存在 kirara.db 时会优先使用它，避免新版空库遮盖迁入的旧库。

桌面应用关闭窗口后仍会在托盘或菜单栏后台运行。备份或停止自动任务前，请从托盘菜单选择「退出」，macOS 也可使用 ⌘ + Q。

数据库和备份包含 Cookie、Token 等私密信息，不应公开。Web 管理界面当前没有内置用户认证；远程部署需自行限制访问并配置带身份认证的反向代理，WebDAV 密码不能替代管理认证。

常见问题

站点测试成功，为什么搜索仍失败？

账号采集和搜索适配可能走不同接口。检查搜索绑定、API 地址、凭据和代理，查看具体站点错误；认证失效、限流或解析失败不等于站点没有资源。

订阅一直不下载？

先检查是否暂停、目标是否已播出，再立即扫描查看搜索词和拒绝原因。核对季集编号、质量限制、最低做种数及站点状态；若已有入队任务，再看队列错误和下载器连接。

RSS 保存了，为什么老资源没有下载？

首次检查只建立基线，规则仅自动处理生效后新发现的条目。需要历史资源时选择条目「补下已有条目」，仍需符合启用规则。信息不足时检查 H&R、免费属性和关联站点，不要反复创建相同源。

任务显示已提交，为什么没有开始下载？

已提交表示下载器接收。检查是否选择暂停添加、qBittorrent 是否排队或暂停、是否有可连接的做种者，以及磁盘、保存目录和网络状态。

Cookie 同步上传成功，为什么站点没变？

查看同步记录是否未变化、跳过或失败。常见原因包括选择了跳过已有站点、域名或认证方式不适用、站点匹配不唯一、备份比已应用数据更旧。按记录修复，可重试项使用「重新同步」。

密码输入框为空，是配置丢了吗？

已保存的凭据不会以明文回传。先查看「已配置」提示并测试连接，留空更新通常保留原值，不要为了填满输入框而清除有效配置。

新标签页能看文档，工作台却无法加载？

手册是独立静态页面，不依赖管理 API。检查云母后端是否运行、页面地址是否正确，以及前端到后端的 API 代理连接。开发环境前端使用 31234 端口，后端默认 3000 端口。

反馈问题时应提供什么？

记录应用版本、运行方式、功能入口、操作步骤和具体错误；可附上已去除敏感信息的截图或相关日志。不要提供完整 Cookie、Token、Passkey、私密 RSS 链接或数据库。
