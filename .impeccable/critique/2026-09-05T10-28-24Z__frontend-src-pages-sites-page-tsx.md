做得好的地方：状态数字可直接筛选并提供 aria-pressed；凭据独立查看、保留和显式清除语义明确；手机采用专门卡片布局且无页面横向溢出，共享弹窗支持焦点循环与归还。

优先问题：

1. P1 错误被包装成没有数据。loadSites 失败后清空列表（sites-page.tsx:828），触发“还没有配置 PT 站点”（1641）；总览失败信息写到被弹窗遮挡的主页面（1266）；手机卡片不展示失败原因/检查时间（1772）。区分加载失败、真实空状态、筛选无结果，在当前卡片或弹窗展示原因和重试入口。建议 $impeccable harden。
2. P1 添加站点过早展开高级配置。默认 14 个请求头，添加窗共有 31 个 input，非全部同时可见；桌面右栏约六成宽度用于请求头，手机提交区需要继续滚动（2051、2156）。默认折叠为“请求头：使用默认 14 项”，优先站点预设、地址、认证，并固定提交区。建议 $impeccable distill。
3. P1 认证字段缺少可靠标签关联。认证方式和 Cookie/API Key/Passkey 的 Label 未绑定输入；浏览器确认 Cookie 无 id、关联 label、aria-label，且 type=text（1426–1501）。补齐 id/htmlFor、默认遮挡及可访问的显示开关，增加就近凭据获取说明。建议 $impeccable audit、$impeccable harden。
4. P2 常用操作被表格宽度挤出。1440px 桌面截图中编辑只露部分、删除需要横滚；手机每行五个 32px 图标，间距 6px（1724、1800）。压缩次要列，确保站点/状态/常用操作可见；保留文字“测试/编辑”，其他放入更多菜单，移动触控目标提高至 44px。建议 $impeccable adapt。
5. P2 容器层级压过任务层级。重复页头、指标卡、筛选外框、表格和逐行描边同样醒目，错误只占小徽标与细小文字（1514、1583、1599、1718）。压缩重复页头、减少逐行描边，把失败原因和处理动作提升层级。建议 $impeccable quieter、$impeccable polish。

认知负担：八项检查五项失败，集中在添加流程。单一焦点、信息分块、视觉层级、最少选择、渐进披露失败；相关分组、一次一个决策、降低记忆依赖通过。每行五个并列操作以及默认展开的高级请求头是主要负担，不能把 input 总数误作同时可见选择数。

情绪旅程：列表的状态数字带来掌控感，添加时的大量高级字段产生迟疑；遇到失败后缺原因和恢复入口，使这一低谷持续。成功反馈已有基础，应明确保存后的测试和刷新下一步。

角色红旗：多站点熟练用户需横滚找编辑，不能只刷新选定失败站点；读屏用户的认证字段和手机重复操作名称缺上下文；首次配置用户需要自己理解 Cookie 和请求头。共享弹窗焦点处理值得保留。
